HTML · Drawbacks

Drawbacks HTML fixes what is on the page and its order. Version 1 is 1,911 px tall because every box is a block in one column.

No placement

HTML has no way to say that two boxes sit side by side.

No look

Colours, borders, spacing and font sizes are the browser's defaults.

Order fixed

Boxes are drawn in the order they appear in the text.

CSS handles the look. Flexbox and the grid, both written in CSS, handle the placement.

Bootstrap grid · Mechanism: the rules behind the classes

Mechanism The grid is a few dozen flexbox rules. A row is a wrapping flex line, a col-8 is two-thirds of it, and padding on every column makes the gutters.

at a 1280 px window, measured in Chrome
1The row's negative margins cancel the container's padding, so columns start at the container edge.
2col-8 takes 66.67% of the row: 760 of 1,140 px.
3Each column pads 12 px on each side. Two neighbours make a 24 px gutter.
.row {
  --bs-gutter-x: 1.5rem;
  display: flex; flex-wrap: wrap;
  margin-right: calc(-.5 * var(--bs-gutter-x));
  margin-left:  calc(-.5 * var(--bs-gutter-x));
}
.row > * {
  flex-shrink: 0; width: 100%; max-width: 100%;
  padding-right: calc(var(--bs-gutter-x) * .5);
  padding-left:  calc(var(--bs-gutter-x) * .5);
}
.col-8 { flex: 0 0 auto; width: 66.66666667%; }

Bootstrap grid · Assumptions

Assumptions The grid works when the stylesheet is loaded and the three classes nest container, row, col.

the grid assumeswhat Chrome draws when it is wrong
the Bootstrap CSS is loadedno columns: col-8 and col-4 are plain blocks, both 1264 px wide and stacked
every col-* is a direct child of a rowthe col keeps its width, but with no flex row round it the next col stacks below
every row sits inside a containerthe row's −12 px margins push it past the window: the page is 1292 px wide in a 1280 px window
a box inside a column fills ita block does; an element given a fixed width in px ignores the column
