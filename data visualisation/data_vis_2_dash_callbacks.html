Callback · Concept

Concept A callback is a Python function. Dash runs it when an input property changes and writes its return values into output properties.

the callback that makes the region dropdown work
Every box is a component id plus one of its properties. Dash connects properties, never whole components.
Callback · Example: the region dropdown

Example The decorator lists five outputs and one input. Called directly as a Python function with North, it returns five values.

@callback(
    Output('kpi-sales', 'children'),
    Output('kpi-orders', 'children'),
    Output('kpi-avg', 'children'),
    Output('by-product', 'figure'),
    Output('by-month', 'figure'),
    Input('region', 'value'))
def update(region):
    d = df if region == 'All' else df[df.Region == region]
    by_p = d.groupby('Product', observed=True).Sales.sum().reset_index()
    by_m = d.groupby('Month').Sales.sum().reset_index()
    return (f"{d.Sales.sum():,}", f"{len(d)}", f"{d.Sales.mean():,.0f}",
            px.bar(by_p, x='Product', y='Sales'),
            px.line(by_m, x='Month', y='Sales'))

Callback · Mechanism: one change, one request

Mechanism The browser holds every property. When one changes, it sends the inputs to the server, which runs the function and returns the outputs as JSON.

Callback · Drawbacks

Drawbacks Every change is a round trip to the server. Changing the region sent 3 requests, and a text box sends one per keystroke.

Latency

The reader waits for the network and the function. A 2-second function means a 2-second dashboard.

Chatty inputs

Typing mouse into a dcc.Input sent 5 requests. With debounce=True it sent 0 until Enter, then 1.

The server does the work

Every reader's every change runs Python on one machine.

dcc.Input(id='search', type='text', debounce=True)   # send on Enter or leaving the box

Outputs · Example: a KPI card as children

    colour = '#B02F3B' if a < df.Sales.mean() else '#14222B'

Patterns · 2 of 5: State and a button

State: read a value without reacting to it A State is sent along with the request, but changing it does not start one. Typing 4000 sent nothing; clicking Apply sent one request.

@callback(Output('applied', 'children'),
          Input('apply', 'n_clicks'),
          State('min-sales', 'value'),
          prevent_initial_call=True)
def apply(n, min_sales):
    return f"{(df.Sales >= min_sales).sum()} orders"

Patterns · 2 of 5: which input fired

Telling two buttons apart with ctx.triggered_id With Apply and Reset both as Inputs, the function gets both click counts. ctx.triggered_id names the one that changed.

from dash import ctx

@callback(Output('applied', 'children'),
          Output('min-sales', 'value'),
          Input('apply', 'n_clicks'),
          Input('reset', 'n_clicks'),
          State('min-sales', 'value'),
          prevent_initial_call=True)
def apply(n_apply, n_reset, min_sales):
    if ctx.triggered_id == 'reset':
        return f"{len(df)} orders", 1000
    return f"{(df.Sales >= min_sales).sum()} orders", min_sales

Patterns · 4 of 5: dcc.Store

Sharing data between callbacks with dcc.Store A Store is a property in the browser that callbacks write and read. Data put in it crosses the network twice: out to the browser and back.

recorded on page load, region All
dcc.Store(id='filtered')

@callback(Output('filtered', 'data'), Input('region', 'value'))
def store(region):
    return subset(region).to_dict('records')
Store what is expensive to recompute and small to send: an aggregate, a list of ids, a user's choices. 500 raw rows cost 150 KB per change.
Patterns · 5 of 5: PreventUpdate and Loading

Leaving an output alone: PreventUpdate and dcc.Loading Raising PreventUpdate returns HTTP 204 and the output keeps its last value. After the search box was cleared, the result still read 200 orders.

recorded: type mo, then clear the box
from dash.exceptions import PreventUpdate

def search(text):
    if not text:
        raise PreventUpdate      # write nothing
    n = df.Product.str.contains(text, case=False).sum()
    return f"{n} orders"
