MCAR

Concept The probability that a value is missing is the same for every row, whatever the row contains.

Missing Completely At Random

P(R = 1 | Xobs, Xmis) = P(R = 1) R 1 if the value is missing Xobs everything the file records Xmis the value that went missing

Missingness carries no information. The rows that lost a value are a random sample of all the rows.

What it permits. Drop the incomplete rows. The estimate stays unbiased; only the sample size falls.
A tablet that drops one answer in fifteen, whichever answer it is, produces MCAR data.

The hollow points are spread through the cloud with no corner of their own. That is the picture MCAR makes, and slides 5 to 17 turn it into a number.

MCAR · Test 1: group-mean comparison

Intuition If missingness is random, the 28 rows that lost gender are a random sample, so their mean age should match the other 372.

400 ages, with the rows missing gender marked
A gap of 1.58 years on 28 rows. The question the test answers is whether shuffling the labels produces gaps that size by chance.

The move

Split the rows into the group that lost the value and the group that kept it, then compare them on a column both groups have.

Which column to compare on

Any complete column will do. age is used throughout this deck so the three tests stay comparable, and because the planted rules for income and health both run through it.

Under MCAR the split is arbitrary, so any statistic computed from it has the same distribution as one computed from a random split of the same sizes.
That sentence is the whole test. The next slide builds the random splits in the browser.

MCAR · Test 1: group-mean comparison

Mechanism The statistic is the difference in mean age; the reference comes from relabelling, and Welch's t-test reaches the same verdict without it.

R = df[col].isna()
obs = df.age[R].mean() - df.age[~R].mean()

null = np.empty(5000)
for i in range(5000):
    idx = rng.permutation(len(df))
    null[i] = (age[idx[:R.sum()]].mean()
             - age[idx[R.sum():]].mean())

p = (np.abs(null) >= abs(obs)).mean()
Welch's t-test replaces the loop with a closed form, and does not assume the two groups share a variance.

Which of the two to run

Take the permutation version when the column is skewed or a group is small, and the t-test when you want a number without a loop. On a clean, roughly symmetric column at these sample sizes they agree to the second decimal.

Assumptions 4 things the shuffle takes for granted, each with a check you can run on the file in front of you.

AssumptionWhat happens when it fails
Rows are exchangeable under the null The shuffle treats all 400 rows as interchangeable. Clustered data breaks this: 20 households of 20 people are not 400 independent draws, and the null comes out too narrow.
The statistic is fixed in advance Choosing the comparison column after seeing the gaps turns a 5% test into something with no stated error rate. Here the column is age, chosen before any output.
A mean is the right summary The test compares means and nothing else. Two groups with the same mean age and very different spreads pass it.
Welch's version: means are near-normal The t reference needs the sampling distribution of each mean to be near-normal. At n = 28 on a skewed column that is a real risk, and the permutation version does not need it.
MCAR · Test 1: group-mean comparison

Drawbacks One column at a time, one moment of the distribution, and a growing multiple-testing bill.

Every pair needs its own test

  • The test compares one incomplete column against one complete column.
  • Three incomplete columns times two complete ones, so six separate tests on a five-column file.
  • Each one carries its own five percent false alarm rate, and one minus 0.95 to the sixth power is 26 percent.
  • On data where MCAR holds everywhere, a spurious rejection about a quarter of the time.
  • A wider table makes this worse fast.

Failing to reject is not a clean bill

  • Gender's p of 0.56 rests on 28 missing rows.
  • A sample that small can hide a real dependence.
  • A large p-value means you did not detect anything, not that there is nothing there.
The test sees means. Missingness that shifts the spread of age but not its centre passes with a large p-value.
It never says which mechanism. A rejection means the missing group differs from the observed group, and both MAR and MNAR produce that.

What Little's test fixes

One statistic for the whole table instead of six, using every column at once. That is the next test.

MCAR · Test 2: Little's test · Little (1988), JASA

Intuition Split the rows by which columns are missing, then compare each group's means on the columns they all share.

One statistic for the whole table

Test 1 asked about one column pair at a time. This asks whether all the pattern means agree with the file's mean, in one number.

Each pattern contributes a Mahalanobis distance between its own means and the file's, weighted by how many rows it holds.
Patterns with 3 rows and 1 row are in the pool too. They carry the same weight per row as the pattern with 200.

Why 8 degrees of freedom

The 8 patterns on slide 2 contribute 12 observed-column slots between them, and 4 parameters are estimated from the data, leaving 8. Change the set of columns you feed the test and the reference changes with it.

MCAR · Test 2: Little's test

Mechanism The statistic needs the file's mean and covariance, and the file has holes, so EM estimates both by filling and refitting until the numbers stop moving.

The mean estimate at each EM pass, against the value the generator used
Both settle by the eighth pass. Income lands near its true mean. Health stops 3.73 above the truth, because EM assumes MAR and health is not.

Where the loop comes from

A missing health score is predicted from the covariance, and the covariance has to be estimated from a table with no holes in it. EM starts from a guess and refines both.

stepwhat it does
EPredict each missing value from the columns that row does have, and record the variance of that prediction.
MRecompute the mean vector and covariance from the filled table.
  • Each hole gets the conditional expectation, one deterministic number. EM never samples, so two runs give the same answer.
  • The variance of that prediction is added back analytically, so the covariance does not shrink.
  • Coefficients are rebuilt for every pattern, since each one observes a different set of columns.
  • The output is the mean vector and covariance. The filled values are scaffolding, rebuilt on each pass and discarded.
  • Drawing from the distribution instead of taking its mean gives multiple imputation, which is lecture 3.
MCAR · Test 2: Little's test

Mechanism continued 1 A weighted Mahalanobis distance per pattern, summed, against a chi-square reference.

d² = ∑j nj (x̄j − μ̂j)′ Σ̂j−1 (x̄j − μ̂j) j each missingness pattern nj rows in that pattern x̄j its mean on the columns it observes μ̂, Σ̂ ML estimates from all the data
  • Under MCAR, d² follows χ² with ∑j kj − k degrees of freedom, where kj counts the columns pattern j observes. Here that is 12 slots against 4 columns, so 8 df.

Getting μ̂ and Σ̂ from incomplete data

for _ in range(iters):            # EM
    for pattern, rows in groups.items():
        B  = S[mis][:,obs] @ pinv(S[obs][:,obs])
        Z[:,mis] = mu[mis] + (Z[:,obs]-mu[obs]) @ B.T
        C[mis][:,mis] = S[mis][:,mis] - B @ S[obs][:,mis]
        T1 += Z.sum(0); T2 += Z.T@Z + len(rows)*C
    mu, S = T1/n, T2/n - np.outer(mu, mu)
The conditional-variance term C is what makes this maximum likelihood rather than mean-filling. Drop it and the statistic here moves from 61.60 to 61.64.
There is no Little's test in scipy or scikit-learn. R has naniar::mcar_test; the forty lines above ship in the notebook.

Why EM and not dropna

μ̂ and Σ̂ have to come from all 400 rows. Estimating them on the 200 complete rows would build the reference out of exactly the rows the test is meant to compare everything against.

MCAR · Test 2: Little's test

Assumptions 4 conditions behind the χ² reference, each with a check you can run on the file in front of you.

AssumptionWhat happens when it fails
Multivariate normality The χ² reference is wrong. Income here has skew 1.91. Take logs (skew 0.05) and the statistic moves 61.60 → 62.21, so the verdict survives. Run that check on any skewed column before quoting a p-value.
Enough rows per pattern x̄j is a mean of nj rows. survey.csv has a pattern with 3 rows and one with 1 row, and those contribute noise to a statistic read against a fixed reference.
One μ and Σ across all patterns The null says every pattern draws from the same distribution. That is the hypothesis being tested, so a rejection can come from any part of it.
EM reaches the ML estimate μ̂ and Σ̂ come from an iteration, not a formula. Here the statistic is stable to two decimals from iteration 400 onward. Confirm that rather than assume it.
MCAR · Test 2: Little's test

Drawbacks One number for the whole file, which is the strength on slide 11 and the weakness here.

It rejects without naming the column

chi2 = 61.60 says something in the table is not MCAR. It does not say which column, in which direction, or by how much.

Not rejecting is not a pass

Large n rejects on differences too small to act on; small n misses real ones. The test answers "is there a difference", never "is it big enough to care about".

MAR

Concept The probability that a value is missing depends on columns you observed, and on nothing you did not.

Missing At Random

P(R = 1 | Xobs, Xmis) = P(R = 1 | Xobs) the missing value drops out of the right-hand side, the observed columns do not

Missingness carries information, and every bit of it is already in the file.

What it permits. Condition on the observed columns and the bias goes away. Imputation and weighting both rest on exactly this.
The name is misleading: nothing about MAR is random. It means the reason for missingness was recorded.

MAR · Test 3: logistic on the missingness indicator

Intuition Turn missing-or-not into a 0/1 column and predict it from the columns you already have.

P(income missing) against age, fitted and observed
The curve is the fit. The rings are the rate actually observed in eight-year bins, and they sit close to it, which is the check that the model shape is right.

Two things Tests 1 and 2 could not do

It takes several predictors at once, so age and education are judged together rather than one test each. And it returns the shape of the dependence, not only its presence.

Test 1 asked whether the two groups differ. This asks how the chance of going missing changes as a predictor moves.

Why it belongs in this section

As a test it targets MCAR. As a model it is the thing imputation and weighting run on, which is why it is taught here rather than beside Little's test.

The null hypothesis is still MCAR: every coefficient zero. A rejection here rules out the same one mechanism the other two ruled out.

MCAR is the claim that no observed column predicts missingness. Step 5 carries the verdict. Step 4 only attributes it.
stepwhat you do with the fit
1Read the coefficients on the log-odds scale. None of them is a probability yet.
2Push the fit through the logistic curve. The chance of withholding falls from 0.345 at age 18 to 0.041 at 65, with education at its mean.
3Exponentiate one coefficient. exp(-0.0532) = 0.948, a five percent drop in the odds per year of age.
4Divide each coefficient by its standard error. Age gives z = -3.95, education gives z = -1.14.
5Compare the fit against the intercept-only model, which gives everyone the same 16.5 percent. LR = 33.61 on 2 df.
6Reject first and attribute second. Step 5 rules out MCAR, then step 4 names age.

MAR · Test 3: logistic on the missingness indicator

Mechanism A linear model on the log-odds, fitted by iterated reweighting, tested by a likelihood ratio.

log( p / (1 − p) ) = β₀ + β₁age + β₂edu p P(value is missing) for that row e^β odds ratio per unit of the predictor LR 2(loglik₁ − loglik₀), χ² on 2 df
  • The Wald p beside each coefficient tests that predictor alone.
  • The LR p tests all predictors together, against a model with only an intercept. Quote it when you want one verdict for the column.

Fitting it

b = np.zeros(X.shape[1])
for _ in range(100):                       # IRLS
    p = 1/(1 + np.exp(-X @ b))
    W = p*(1-p)
    b = b + solve(X.T @ (X*W[:,None]), X.T @ (y-p))

se = np.sqrt(np.diag(inv(X.T @ (X*W[:,None]))))
Newton's method on the log-likelihood. Each step reweights the rows by p(1-p), so rows the model is unsure about count most.
sklearn.linear_model.LogisticRegression regularises by default and reports no standard errors. For a test, either turn the penalty off or use the twelve lines above.

Reading the two p-values

The Wald p beside a coefficient can be large while the LR p is small, when two predictors carry the same signal. Quote the LR p for the column and the Wald p only for the predictor you are naming.

  • A likelihood asks one thing of a model: what probability did it assign to what actually happened? Row by row. A respondent who withheld income contributes the model's p for that person. A respondent who reported it contributes 1 minus p. Multiply all 400, or equivalently add the logs.
  • The fitted model has three parameters, and each person gets their own probability from the equation. Its log-likelihood is a sum over 400 rows where every row uses its own p, and it comes to -162.34. There is no shortcut for it.
  • The null model has one parameter. It has no age or education term at all, so it gives everyone the same p. This is a separate fit, so you re-estimate the intercept from scratch. That is the step that is easy to miss.
  • You cannot take 1.2667 from the other equation and use it here. If you did, everyone would get a log-odds of 1.2667, a probability of 0.78, and the model would claim that 78 percent of respondents withheld income when only 16.5 percent did.
  • Re-maximising over the intercept alone gives -1.6215, and pushing that through the logistic curve gives 0.165.
  • For an intercept-only logistic model the maximum-likelihood probability is always the sample proportion. Here that is 66 divided by 400. You can check the two directions agree: the log-odds of 0.165 is ln(0.165 / 0.835), which is -1.6215.
  • Once every row has the same p, the sum of logs collapses, because there are only two distinct terms: 66 rows withheld, each contributing ln(0.165), and 334 rows reported, each contributing ln(0.835).
  • That 0.165 is not chosen for convenience, it is the value that maximises the expression. Push it either way and the score falls, as the table on the left shows.
  • So -179.15 is the best any MCAR-shaped model can do on this data. That is the number the alternative has to beat, and it is worth saying that out loud: you are not comparing against a strawman, you are comparing against the best flat model there is.
  • The null model is the fitted model with the two slopes forced to zero and the intercept re-estimated. That is what nested means, and it is why the degrees of freedom are 2: two parameters constrained, the third left free.

  • Now p varies by person. The four respondents on the left show what each model gave them and what the fit gained or lost on that row.
  • Respondent 70 is 63 and withheld income anyway, which the model considers unlikely, so that row costs 1.479. Note that the fit is not better everywhere: the model buys its overall gain by being confident where it is right and paying for it where it is wrong.
  • Adding all 400 rows gives -162.34, a gain of 16.80. Where that gain comes from is the interesting part.
  • The young withholders alone contribute more than the total, which means the older withholders are handing some of it back. The model earns almost everything it earns by predicting that young people withhold, which is exactly the rule the generator used.
  • A difference of log-likelihoods is the log of a ratio. Undo the log and e to the 16.80 is about 20 million. The observed pattern of who withheld income is roughly 20 million times more probable under the fitted model than under the flat one.
  • That ratio is not yet a test, because a bigger model always fits better, even on noise. You need to know how large a gain two extra parameters buy you by luck alone.
  • Wilks' theorem answers it: under the null, twice the log-likelihood gain follows a chi-square distribution with degrees of freedom equal to the number of parameters you restricted.
  • The doubling is not cosmetic. Without it the quantity would not match a chi-square curve, and the factor of two comes out of the quadratic approximation to the log-likelihood near its maximum.
  • The degrees of freedom track parameters rather than columns, which is why adding one predictor would have given 1 df and adding five would give 5.
  • The whole comparison is a single test of a single claim, so the false-alarm rate you asked for is the one you get, unlike reading two coefficient p-values and taking whichever is smaller.

Linear in the log-odds A predictor whose effect turns around mid-range fits as a flat line and reports p near 1. Check by binning: the rings on slide 21 sit on the curve, so age is safe here.
The predictors are complete age and education_years have no missing values. When a predictor has its own gaps you are fitting on a subset chosen by a second mechanism.
No separation If some combination of predictors perfectly splits missing from observed, the coefficient runs to infinity and the standard error with it. Watch for se in the tens.
Enough missing values per predictor 66 missing values and 2 predictors is comfortable. 28 and 2, as for gender, is thin enough that a real effect can be missed.
Three of the four are checkable on this file. Bin the predictor for linearity, count missing values in each predictor, read the standard errors for separation.
MAR · Test 3: logistic on the missingness indicator

Drawbacks The coefficient reports which observed column predicts missingness, which is a different question from what caused it.

A predictor is not a cause

OR = 0.948 on age says the missing rows are younger. If the real driver is something correlated with age and absent from the file, age reports the same coefficient.

The null is still MCAR

LR p = 5.0e-08 rejects "no dependence on anything observed". It does not establish that the dependence stops there.

Only observed columns can enter the model. The one variable that would separate MAR from MNAR is the missing value itself.
So a clean fit on age is evidence for MAR only if you already believe nothing unrecorded is driving the gaps.

MNAR

Concept The probability that a value is missing depends on the value itself, which is the one thing the file does not contain.

Missing Not At Random

P(R = 1 | Xobs, Xmis) depends on Xmis and Xmis is, by construction, the part of the data you do not have

Conditioning on the observed columns leaves the bias in place, because those columns are a stand-in for the one that drove the missingness.

Why no test reaches it. A test compares what it can see. MAR and MNAR differ only in a column that is absent from every row where it matters.

The hollow points fill the bottom of the cloud at every age. The downward slope is what lets age stand in for the score in any model fitted on the file.

MNAR · Sensitivity analysis · pattern mixture

Mechanism Split the mean into the part you measured and the part you assumed: μ = μobs + πδ.

μ = (1−π) μobs + π μmis = μobs + π (μmis − μobs) = μobs + π δ π fraction missing = 0.360 μobs mean of the observed = 87.03 δ how much lower the missing group is, which you supply
Two of the three numbers are counted off the file exactly. The third cannot be estimated from any data you hold.

What the split buys

It moves the unidentifiable part into a single named number. Instead of an estimate that hides an assumption, you report an estimate as a function of one.

δ = 0 is the complete-case answer, 87.03. Every method in Lecture 3 that fills from observed columns sits near there, whether or not it says so.
The same algebra works for proportions, regression coefficients and differences of means. The parameter changes; the shape does not.
MNAR · Sensitivity analysis

Assumptions 4 conditions behind μ = μobs + πδ, one of which is the point of the method.

AssumptionWhat happens when it fails
δ is supplied, not estimated No feature of the data identifies it. A single reported mean is one δ chosen and not written down, and this method's job is to put that choice on the page.
π is the true missing fraction 0.360 is a count, so it is exact. Sentinel values still read as present, though, and Lecture 1 found 5,796 of those hiding as "-" in the index file.
One δ for the whole column The formula assumes the missing group sits a fixed distance below the observed one. When the shift differs by subgroup, run the analysis per subgroup.
μobs is right for the observed The observed rows are taken at face value. A separate measurement problem inside them breaks the decomposition before δ is reached.

What to report

A range of δ you can defend, the estimate at each end, and whether the conclusion changes anywhere inside it. Chasing a sample of non-respondents is the only move on this slide that produces evidence rather than an assumption.

Choosing a δ to defend

Argue it from the question, not the file. Health scores are withheld by people who score badly, so δ is negative; a survey where the top earners skip the income question would need a positive one.
