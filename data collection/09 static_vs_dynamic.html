Static vs Dynamic Pages

What requests sees vs what a browser sees  ·  DA2402 · Data Collection

What requests.get(url).text returns

The server sends back the page's initial HTML skeleton — no JavaScript has run yet. The product listing container is empty; all the data will be injected later by the browser running the site's JS bundle.

view-source:https://shopnow.example.com/laptops
Server response (raw HTML)
<!DOCTYPE html> <html lang="en"> <head> <meta charset="UTF-8"> <title>ShopNow — Laptops</title> <link rel="stylesheet" href="/static/app.css"> </head> <body> <nav class="navbar">ShopNow</nav> <!-- React/Vue app mounts here — nothing inside at page-load time --> <div id="app"> </div> <!-- ← EMPTY! --> <div id="product-listing" class="grid"> <!-- products will be injected by JavaScript --> </div> <!-- ← EMPTY! --> <script src="/static/vendor.bundle.js" defer></script> <script src="/static/app.bundle.js" defer></script> <!-- all the logic lives here --> </body> </html>
JS not yet run

What BeautifulSoup finds when it parses this

soup.find_all('div', class_='product-card')
→ returns [] — an empty list.

The container div is there, but it has no children. There are no product names, no prices, no ratings.
✗soup.find('div', id='product-listing').text → ""
✗len(soup.find_all('div', class_='product-card')) → 0
✗soup.find('span', class_='price') → None
Why? This is a Single-Page Application (SPA) built with React. The server returns only a thin shell. Product data is fetched from a JSON API (/api/products?cat=laptops) after the browser parses and executes the JS bundle. requests never sees that API call happen.

The highlighted lines are the clue: an id="app" div or an empty container with a comment like "injected by JS" is a tell-tale sign of client-side rendering.

What Selenium + BeautifulSoup now finds

After waiting for the JS to execute (WebDriverWait until element visible), the DOM is fully populated.
✓len(driver.find_elements(By.CLASS_NAME, 'product-card')) → 4
✓driver.find_element(By.CLASS_NAME, 'pprice').text → "₹1,19,990"
✓soup.find('div', class_='pname').text → "Dell XPS 15"
Typical Selenium pattern: 
from selenium import webdriver
from selenium.webdriver.common.by import By
from selenium.webdriver.support.ui import \
    WebDriverWait
from selenium.webdriver.support import \
    expected_conditions as EC
from bs4 import BeautifulSoup

driver = webdriver.Chrome()
driver.get("https://shopnow.example.com/laptops")

# wait until at least one card appears
WebDriverWait(driver, 10).until(
    EC.presence_of_element_located(
        (By.CLASS_NAME, "product-card")
    )
)
soup = BeautifulSoup(driver.page_source, "html.parser")
cards = soup.find_all("div", class_="product-card")
for c in cards:
    print(c.find("div", class_="pname").text,
          c.find("div", class_="pprice").text)

Why do they differ? — Client-side rendering & AJAX

The web has two broad patterns for how pages are built. Knowing which one you're dealing with determines your scraping strategy before you write a single line of code.

Server-Side Rendering (SSR) — "Static" from the scraper's point of view
The server builds the complete HTML and sends it. requests.get(url).text already contains all the data. BeautifulSoup can parse it immediately. This is the traditional model (PHP, Django templates, older Rails sites, Wikipedia, most government portals).
Client-Side Rendering (CSR / SPA) — "Dynamic" — needs a real browser
The server sends a thin HTML shell + JavaScript bundle. The JS runs in the browser, calls a JSON API (AJAX / fetch), and writes the product/content HTML into the DOM after page load. requests never executes that JS, so it sees the empty shell. You need Selenium (or Playwright, Puppeteer) to drive a real browser.

Rule of thumb: which tool do you need?

Signal you observe Likely rendering model Use requests? Use Selenium?
Page source (Ctrl-U) already has the data you want Server-side / static HTML Yes ✓ Not needed
Source has <div id="app"></div> or <!-- injected --> Single-Page App (React / Vue / Angular) No ✗ Yes ✓
Network tab shows XHR / fetch calls to /api/… AJAX data loading Maybe — hit the API directly Or use Selenium
Content appears only after scrolling (infinite scroll) Lazy-load / virtual DOM No ✗ Yes ✓ (scroll + wait)
Login, button click, or dropdown selection required Dynamic interaction needed No ✗ Yes ✓
Well-documented public REST / GraphQL API available Any Yes ✓ (hit API directly) Overkill

Quick diagnostic checklist — before you write code

  1. View source (Ctrl-U / Cmd-U) — is your data in there? If yes, requests + BeautifulSoup works.
  2. Inspect element → Network tab → reload — look for XHR/Fetch requests returning JSON. If the data comes from /api/…, you might be able to call that API directly (much faster than Selenium).
  3. Check for framework fingerprints — id="root", id="app", data-reactroot, __NEXT_DATA__, nuxt in the source → SPA → use Selenium.
  4. Try requests first — if response.text has your data, you're done. It's 10–100× faster than spinning up a browser.
Performance trade-off: requests + BeautifulSoup can scrape thousands of pages per minute. Selenium is limited to ~5–20 pages per minute (browser startup, JS execution, waits). Only pay the Selenium cost when you truly need it.
Reference: Mitchell, Web Scraping with Python, Ch. 10 "Scraping JavaScript"; Selenium docs "WebDriverWait & expected_conditions". See also the official Playwright docs for a modern Selenium alternative.
